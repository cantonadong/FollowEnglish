## 1. 需求原文（逐条对应，确保100%覆盖）

1. web 应用，调用浏览器实现
2. 允许用户上传视频，支持通用格式 mp4、flv、mov 等常见格式
3. 按视频自动拆分每一句英文，自动识别添加英文字幕（带时间戳）
4. 用户按键盘 左、空格、右，可切换播放上一句、下一句、播放/暂停
5. 按 m 显示/隐藏字幕
6. 按 - = 缩放字幕字号大小
7. 字幕位置同常见视频播放器中的字幕位置
8. 该应用是方便用户练习英文听力，精听、shadowing 使用

---

## 2. 业务流程

```
用户打开浏览器 → 上传页
   ↓ 选择/拖拽视频文件
后端接收文件 → 转码为浏览器兼容格式(mp4 h264+aac) → 提取音频
   → 用 ffmpeg whisper 滤镜做本地语音识别，生成带时间戳的英文分句字幕
   ↓ 处理完成
自动跳转播放页 → 视频 + 字幕 + 句子列表同步显示
   ↓ 用户使用键盘快捷键
逐句精听 / shadowing 跟读练习
```

处理是**异步**的：上传接口立即返回一个 `jobId`，前端轮询 `/api/jobs/:id` 获取状态机：

`uploading → transcoding → transcribing → ready`（任一环节失败进入 `error`，附错误信息）

## 3. 页面设计

### 3.1 上传页 `/`

- 大面积拖拽区 + "选择文件"按钮，提示支持格式：mp4 / mov / avi / mkv / flv / webm / wmv
- 状态展示（同一区域按状态切换，不跳转页面直到 ready）：
  - **normal**：拖拽提示 + 支持格式说明
  - **uploading**：上传进度条（百分比，基于字节数）
  - **transcoding**：转码进度条（基于 ffmpeg 输出的时间进度）
  - **transcribing**：识别中，不确定进度条 + 已用时计时（whisper 滤镜无法给出精确百分比）
  - **error**：错误信息 + "重试"按钮
  - **ready**：自动跳转播放页
- 无历史记录/登录体系（单机本地工具定位，简化范围）

### 3.2 播放页 `/player/:jobId`

布局（贴近主流视频网站/播放器常见样式）：

- 顶部/主体：16:9 视频区域，居中，最大宽度自适应窗口
- **字幕位置**：视频底部居中，距底边留出舒适间距（约 12% 视频高度，不贴边，参考主流播放器字幕位置），最大宽度 80%，文字居中换行
- 字幕样式：白字 + 黑色描边/半透明黑底（保证任意视频背景下可读），字号可调
- 播放控制条（原生 video 控件之外的自定义控制条，或复用浏览器原生控件 + 额外快捷键提示条）：
  - 播放/暂停按钮
  - 进度条（可拖拽跳转）
  - 当前句 / 总句数 指示，例如 "12 / 87"
  - 字幕开关按钮（同 M 键）
  - 字号 +/- 按钮（同 -/= 键，供无键盘/触屏场景使用）
- 右侧或下方可选：整句字幕列表（点击某句可跳转播放），当前播放句高亮 —— 便于用户视觉定位精听进度

### 3.3 键盘快捷键（全局，播放页生效）

| 按键 | 行为 |
|---|---|
| `Space` | 播放 / 暂停 切换 |
| `←` (ArrowLeft) | 专指"上一句"：无条件跳到**上一句**开头（不做"播放超过阈值先回到本句开头"的音乐播放器式处理），已是第一句则停留原地 |
| `→` (ArrowRight) | 跳到**下一句**开头；若已是最后一句则停留原地 |
| `M` / `m` | 显示 / 隐藏字幕（切换，不影响音视频播放） |
| `-` | 字幕字号连续减小 |
| `=` / `+` | 字幕字号连续增大 |

细节：

- 跳句后**保持原播放/暂停状态**（暂停时跳句仅更新画面帧，不自动播放；播放中跳句无缝续播）
- 字号调整：以视频高度的百分比为单位（`cqh`，随视频尺寸自适应），连续可调，每次按键 1% 步进，范围 3%~25%（**最大不超过视频高度的 1/4**，最小保证可读），到边界不再增减，可持续按不会卡死
- 快捷键仅在页面主体聚焦、且未处于文本输入框中时生效，避免与浏览器默认行为冲突（阻止 Space 触发页面滚动、`-`/`=` 触发浏览器缩放等默认行为）

## 4. 功能逻辑细节

### 4.1 句子拆分与字幕时间戳（**关键需求，准确性优先**）

用户明确要求：**句子拆分必须准确，不能把语义/语法上不完整的一句话截断**，除非该句本身很长（此时允许在自然停顿处拆分为可接受的片段）。

- 使用 ffmpeg 内置 `whisper` 音频滤镜（whisper.cpp，本地运行，`language=en`）对提取出的音频进行转写，开启 **word-level 时间戳**（whisper.cpp 原生支持逐词时间戳）
- **不能**直接把 whisper 基于停顿/静音检测自动给出的 segment 当作最终"一句"——因为 whisper 的分段依据是声学停顿，可能出现在语法不完整处（如从句中间换气）截断
- 正确处理流程：
  1. 取 whisper 输出的逐词时间戳序列（word + start + end）
  2. 按句末标点（`.` `!` `?` `...` 以及部分省略号/引号收尾情况）重新切分句子边界，而不是按 whisper 的 segment 边界切分
  3. 每句的 `start` = 该句第一个词的开始时间，`end` = 该句最后一个词的结束时间
  4. 若某一句拆出来过长（超过设定的时长/字数阈值，如 > 15 秒或 > 25 词），允许在句内**语法完整的自然断点**（如连词、从句边界对应的标点如逗号）处再拆分为多个片段，避免用户长时间等不到"下一句"
  5. 若识别结果没有标点（whisper 英文模型通常会输出标点，但极端情况下可能缺失），需要有兜底策略（如按较长静音间隔 + 词数上限拆分），并在后续联调阶段用真实视频验证效果
- 后端将最终句子数组整理为：`[{ index, start, end, text }]`，作为前端"上一句/下一句"导航与字幕展示的唯一数据源
- 该部分逻辑需要用真实素材反复验证调优，是第 8 步"后端字幕生成"的核心工作，不是简单调用一次 ffmpeg 命令就能完成的

### 4.2 视频兼容性

- 上传后统一用 ffmpeg 转码为 `mp4 (h264 + aac)`，保证浏览器 `<video>` 原生播放、精确跳转（seek）不受原始编码影响
- 原始文件转码后即可删除或保留（默认保留以便调试，可配置自动清理策略）

### 4.3 上传限制

- 支持格式：mp4, mov, avi, mkv, flv, webm, wmv（ffmpeg 支持的常见容器）
- 单文件大小上限：默认 2GB（本地工具场景，可通过环境变量调整）

## 5. 视觉规范（简版，Preview 阶段可微调）

- 配色：深色背景（播放器场景常见），主色调中性灰/黑，强调色用于按钮高亮、当前句高亮
- 字体：系统默认无衬线字体（视频字幕通用做法），字幕文字加黑色描边或半透明底条保证可读性
- 交互反馈：按键触发的跳句/字号变化需有轻量视觉反馈（如字幕短暂高亮闪烁、字号变化即时生效无动画延迟）
- 深浅色模式：跟随系统（若无特殊要求，默认深色为主，播放器场景更常见）

## 6. 技术架构

### 6.1 技术选型（已与用户确认）

| 层 | 选型 | 说明 |
|---|---|---|
| 前端 | React + Vite + TypeScript | SPA，两个路由：上传页 / 播放页 |
| 后端 | Node.js + Express | 承担上传接收、ffmpeg 调度、任务状态管理、静态资源服务 |
| 视频转码 | ffmpeg（系统已安装，8.1 full build） | 统一转码为 mp4 h264+aac |
| 语音识别 | **ffmpeg 内置 `whisper` 滤镜**（whisper.cpp，本地离线） | 免费、离线、隐私友好，且**无需额外起 Python 进程**，比"Node 调用 Python Whisper"方案更轻量，符合"节省内存和CPU"的要求 |
| ASR 模型 | `ggml-base.en.bin`（英文专用小模型，约 142MB） | 优先节省资源；如识别精度不满足需求，可平滑升级到 `small.en`（约 466MB），仅需替换模型文件+改配置，无需改代码 |

> 关键发现：本机 ffmpeg 8.1 编译时已 `--enable-whisper`，自带 `whisper` 音频滤镜，可直接
> `ffmpeg -i audio.wav -af "whisper=model=models/ggml-base.en.bin:language=en:queue=30:max_len=1:format=json:destination=out.json" -f null -`
> 一步得到逐词时间戳，因此**不需要安装/调用 Python + openai-whisper/faster-whisper**，架构更简单、资源占用更低。
> 实际调试中发现两个必须调整的参数（否则识别准确率很差或无法获得逐词时间戳）：`queue`（滤镜内部冲刷窗口，默认3秒会导致识别破碎，改为30秒）与 `max_len=1`（强制输出近似逐词的时间戳，用于自行按标点重组句子）。完整踩坑细节见 `docs/log.md`。

### 6.3 数据流

1. 前端 `POST /api/upload` (multipart/form-data) → 后端存原始文件，创建 job，返回 `jobId`，立即触发异步处理管线
2. 管线：ffmpeg 转码 → ffmpeg 提取 16kHz 单声道 wav → ffmpeg whisper 滤镜生成字幕 json → 更新 job 状态为 `ready`
3. 前端轮询 `GET /api/jobs/:id`（间隔约 1s）获取状态 + 进度
4. `ready` 后前端请求 `GET /api/jobs/:id/subtitles` 拿字幕句子数组，`GET /media/:id.mp4` 播放视频
